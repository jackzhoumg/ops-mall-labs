# 故障演练前检查清单

演练负责人在演练前一天和演练开始前各过一遍。任意一项“否”，演练推迟。

## 一、演练方案（提前 1 天）
| 检查项 | 是 / 否 | 备注 |
|---|---|---|
| 写清楚了稳态假设（哪个指标、阈值多少、用什么工具看） | | |
| 写清楚了故障类型、注入目标、持续时间 | | |
| 爆炸半径已限定：命名空间、标签、数量（mode / value）、duration | | |
| 写清楚了中止条件（什么情况立刻停） | | |
| 写清楚了中止方法（abort.sh / 删除实验对象），并有人演示过 | | |
| 相关团队（开发、DBA、客服）已知晓演练时间 | | |
| 避开了业务高峰、发布窗口、大促 | | |

## 二、系统状态（开始前 30 分钟，可用 scripts/preflight-check.sh 自动检查大部分）
| 检查项 | 是 / 否 | 备注 |
|---|---|---|
| 集群节点全部 Ready | | |
| 目标应用 >= 2 副本且全部就绪，分布在不同节点 | | |
| 目标应用有 PDB | | |
| 没有残留的混沌实验 | | |
| 监控、告警、日志正常（Grafana 能看到 mall-api 指标） | | |
| 最近 1 小时没有未关闭的告警和事故 | | |
| 数据库有可用备份（SRE-3） | | |

## 三、人员与沟通
| 检查项 | 是 / 否 | 备注 |
|---|---|---|
| 演练负责人、执行人、观察记录人已到位 | | |
| 已在值班群发“演练开始”通知（时间、范围、联系人） | | |
| 演练期间如果有真实事故，立即中止演练，优先处理真实事故 | | |

## 四、演练后
| 检查项 | 是 / 否 | 备注 |
|---|---|---|
| 混沌实验已全部删除，稳态已恢复 | | |
| MALL_DEBUG 已关回 false | | |
| 已发“演练结束”通知 | | |
| 演练记录 / 复盘文档已完成，改进项有负责人和截止日期 | | |
